# Animation: clips, procedural layers and what is next

> **Status (2026-10-21): the procedural layer is built** (walk cycle from speed, look-at, springs, a bob and a lean; `src/sim/procedural_anim.*`, Lua `model.procedural` / `model.look_at`, tests/test_procedural.cpp). The clip editor, blending and state machines, events on clips and two-bone IK with foot placement are the next steps (below).

## What there is
A rig (`world/rig.hpp`) is a model with named parts, pivots and keyframed clips (rotation / offset / glow per part, a loop flag); `AnimatedModels` makes every part a kinematic voxel body posed each tick from the playing clip; the agents of docs/AGENTS.md walk with a clip. Everything is a function of the tick number (a recording replays it exactly): the bodies push dynamic bodies, so poses are simulation state, not decoration.

## Procedural layers: rules over the clip
A layer is a few rules keyed by **part names**, applied on top of the clip's pose (`Rig::evaluate(clip, t, extra)`: a rotation per part about its pivot, in its parent's frame, after the clip's). It needs no clip and no editor. The state (a phase, the head's angles, spring angles) advances once per tick from the model's place (`origin` between ticks gives its speed and acceleration) with the deterministic math only (`core/dmath.hpp`).
```lua
model.procedural(m, {
    walk = { legs = {"leg_l", "leg_r"}, arms = {"arm_l", "arm_r"}, leg_amplitude = 35, arm_amplitude = 28,
             cycles_per_m = 0.8, full_speed = 1.6, bob = 1, lean = 4 },
    look = { part = "head", limit_yaw = 70, limit_pitch = 40, turn_rate = 420, forward = {0, 0, 1} },
    springs = { { part = "tail", axis = "x", stiffness = 90, damping = 7, gain = 0.6, max = 55 } },
    limbs = { { part = "wing", phase = 0, amplitude = 40, axis = "z" } },        -- any limb that swings with the stride
})
model.look_at(m, x, y, z)      -- the head turns towards a world point (voxels), within its limits, at `turn_rate`
model.look_at(m)               -- looks ahead again
model.procedural(m)            -- removes the layer (the rest pose or the clip again)
model.procedural(m, { from_roles = true })   -- the rules the rig's roles imply (below); sections given next to it replace the matching part
model.rig(m)                   -- the rig description as a table: parts (parent, pivot, joint), roles, clips
model.rig(m, { roles = "infer", joints = { head = { type = "ball", cone = 70 } } })   -- changes it first
```
- **Rig description** (round 22, `world/rig.*`, `world/rig_json.*`): every part may have a **joint** (`RigJoint`: a hinge about an axis with `lo` / `hi` degrees, or a ball with a `cone` and a `twist`, axes in the model's frame) and the rig has **roles** (`RigRoles`: hips, head, spine, legs and arms as upper / lower / end with a `pole`, tail links, forward). The rules of the procedural layer (look-at, springs, the walk swing, IK) are kept inside the joints (`Rig::evaluateWith`: a part with an override is clamped; a clip is not limited). `Rig::inferRoles()` guesses roles from part names (hips / pelvis, head, torso / chest / spine*, thigh / upper_leg / leg / hind_leg / front_leg + shin / calf / lower_leg + foot / paw / hoof, upper_arm / arm / wing + forearm + hand, tail* / antenna* / cape) and gives the parts the limits the roles imply: a ball of 60 degrees at the hip, a knee hinge 0..140 (bending the way the pole points), a ball of 170 at the shoulder, an elbow hinge -150..0, 70 at the neck, 20 along the spine, 60 in a tail. The kit's `walker` has legs without a shin, so it swings but has no IK. **File**: a trailing `RIGX` chunk after the clips (version, per part the joint, then the roles as JSON by part *name*), written only when a joint or a role is set; readers that stop after the clips ignore it, a damaged chunk is a warning and the rig loads without it. `proceduralFromRoles` builds the rules from the roles (the legs swing in turn and get IK where they have a shin and a foot, the arms against them, the head looks, the tail links are springs). **Tools**: Lua `model.rig(m [, edit])`, MCP `animated_list`, `animated_spawn`, `model_rig {id}`, `model_rig_set {id, roles | joints | clear_joints, save}` (recorded as `model_rig_edit`; `save` also writes the .vxm), `model_procedural {id, rules | remove}` (recorded as `model_procedural`, the same JSON as the Lua table: `sim/procedural_json.*`), `model_look_at {id, x, y, z | clear}`. Not built: workspace ops `rig_role` / `rig_joint` and a manifest `rig = {...}` (the workspace edits plain voxel models, not rigs: roles and joints are set with these tools on a spawned model and saved).
- **Springs v2** (round 22): a spring's `drive` is `accel` (the model's acceleration, as before), `parent` (how fast its parent turns about the spring's axis, `parent_gain` degrees per rad/s, default 8: a tail with links `tail1 -> tail2 -> tail3` follows the body's turning, each link feeling its parent's absolute turning) or `both` (default); `sag` degrees droops the part towards gravity (a cape; measured along the way it hangs: the middle of its voxels from its pivot). The parents' turning is measured from the previous tick's final poses (`finishProcedural`), so it lags one tick.
- **Ragdoll** (round 22): `ragdoll = { impulse = 40, fall_time = 0.6, recover = 0 }` in the rules (`model.ragdoll(m, true, ix, iy, iz)` / MCP `model_ragdoll` do it on request): a contact of at least `impulse` N s on any part (`VoxelBody::hitImpulse`, the largest normal impulse of one contact in the last solve; a crate that hits it, a falling load) makes **every part body dynamic** again (mass and inertia kept from the spawn) and joins each to the nearest ancestor that has a body by a joint at its pivot, from the rig's joint (hinge with its limits shifted by the angle it has now, ball with its cone, default a 30 degree ball). For `fall_time` seconds the joints are **powered**: a PD servo turns every part towards its animated pose relative to its parent's body, strength fading to nothing, so a hit model staggers before it goes limp. The model's origin follows the hips' body. `model.ragdoll(m, false)` (or `recover` seconds) gets it up: the servo ramps to full over half a second, then the joints go, the parts are driven again and the model stands where the hips lie (on the ground found under them). Nothing here is read back by gameplay except through the bodies, which are in the state hash; the hit is deterministic (same contacts, same impulses). Not built: agents that stop walking while ragdolled (P7).
- **Quadrupeds** (round 22): `quad = { fl, fr, bl, br, gait = "auto" | "walk" | "trot" | "pace" | "gallop", gaits = {{ name, from_speed }, ...}, spine = {...}, spine_flex = 8 }` (or `from_roles = true` on a rig with four legs: the legs are ordered by where their hips are along the model's front and side). The swing of the four upper leg parts follows a **gait table** (fractions of a cycle: walk fl 0, fr 0.5, bl 0.75, br 0.25; trot diagonal pairs; pace lateral pairs; gallop bl 0, br 0.1, fl 0.5, fr 0.6) with a swing scale and a stride length per gait; `auto` walks below 1.8 m/s, trots to 4.5 and gallops above (10 % hysteresis; the ladder is yours to change); a change of gait cross-fades the leg *angles* over half a cycle, so no leg jumps. A gallop flexes the `spine` parts, bobs the head and leaves the ground once a cycle (twice the walk's `bob`). The front legs of the IK pair get their pole backward (an elbow), the hind legs forward.
- **Frames** (round 22): the model's own frame is +y up, `forward` its front (default +z), side = up x forward. Limb and spring `axis` is a letter (`"x"` the side, `"y"` the up, `"z"` the forward) or `{x, y, z}` in that frame. The world up (the plane the speed is measured in, the bob, later where the feet look for the ground) comes from the gravity field at the model (`AnimatedModels::gravity`), else the model's own up. A model placed by `model.move` is a **cut** (no speed that tick); something that walks (the agents) uses `AnimatedModels::follow`. `model.look_at` on a model without a look rule is an error. Backwards walking runs the cycle the other way; standing brings the legs together; the spring drive is filtered and clamped (±50 m/s^2), the measured speed to 30 m/s.
- **Legs** (round 22, `ik = { legs = {...} }`): a leg is three parts, `upper` (pivot = hip), `lower` (child of upper, pivot = knee), `foot` (child of lower, pivot = ankle); `pole` is the direction the knee points (default: the model's forward), `foot_height` the voxels from the ankle's pivot down to the sole. After the first posing pass the ankle's animated place is corrected so it stands on the ground under it (a CPU ray along -up from `lift` m above the ankle, `reach` m long, filtered over a few ticks; a foot in the air moves only up, to clear the ground; no ground in reach: the animated place), the pelvis sinks (at most `max_drop` m) towards a lower foot, and the thigh and shin get replace overrides from a two-bone solver (`solveTwoBone`: the law of cosines with the knee in the pole's plane; a target out of reach gets a straight leg). `foot_level` tilts the foot to the slope while it stands, `foot_placement = false` follows the animation exactly. The ray runs on the CPU world, so a replay and every net peer find the same ground. Needs `AnimatedModels::world` (set by the game).
- **Foot lock and turning** (round 22): a foot that stands (it moves against the way the model goes, or the model stands still) is **planted**: its ankle is pinned in the world (the height still follows the ground), so the hips pass over it without sliding; it is released into a **step** (10 ticks, a 2 voxel arc, smoothstep) when the pin is more than half a voxel out of reach, or when the model has turned more than 50 degrees since it was planted (a quarter turn of an agent): one leg at a time, so a turn in place is two steps. `ik.foot_lock = false` turns it off. `turn_smoothing = N` ticks (default 0; agents 15, P7) turns the body about the model's bottom centre from where it was shown to the new rotation (`ProceduralState::visRot`), so the voxel body does not snap with the agent's quarter turns.
- **Walk cycle**: the phase advances with the distance walked (`cycles_per_m`), the swing grows with the speed up to `full_speed` m/s (standing still: none, it settles back), legs in turn with a half cycle between, an arm against the leg on its side; `bob` lifts the whole model (voxels, twice a cycle), `lean` tips the root forward (degrees at full speed).
- **Look-at**: the direction from the head's pivot to the target in the model's frame, as yaw about the up axis and pitch about the side axis from the rest direction (`forward`), clamped to the limits and approached at `turn_rate` degrees a second; a target behind the model makes the head look as far round as it can.
- **Springs**: secondary motion: a tail, a cape or an antenna is a damped spring driven by the model's acceleration along its forward direction (it lags when the model speeds up, swings forward when it stops) and comes to rest.
- An unknown part name is an error naming the parts (`model.procedural` checks it). A model without a layer is untouched.

## Rigged models from a script (round 28)
`tools/make_creatures.py` writes rigged `.vxm` files (VXM4: voxels with paint and a texture name, a part table, a part map, clips, an `ANIM` chunk with clip events) from Python, with no engine running: a small canvas of shapes (`box`, `ellipsoid`, `line`) tagged with part names, pivots per part, keyframes per clip. The part names follow `Rig::inferRoles` (pelvis / torso / head, `thigh_l` -> `shin_l` -> `foot_l`, `upper_arm_l` -> `forearm_l`, `front_leg_l` -> `lower_leg_fl` -> `foot_fl`, `tail1`), so `agent.spawn{animation = "auto"}` walks the bipeds with IK and the quadrupeds with a gait; the clips are what the rules do not do (a slime's hop, an `attack` swing, an `idle` sway). The six it makes (slime, skeleton, goblin, rabbit, deer, chicken) are in `projects/creature_test` and `assets/prefabs/creatures`. A model that names a built-in texture (`smooth`: flat paint, no planks or speckle) loads outside a project too: the loader falls back to the built-in texture table.

### Cross-fades and layers
`model.play(m, clip, speed, loop, fade_ticks)` / MCP `model_play {id, clip, speed, loop, fade}`: with `fade` the pose blends from what played before over that many ticks (rotations by `nlerp`, offsets and glow linearly). Underneath, `Rig::sampleLocal(clip, t)` gives what a clip says (a rotation, an offset and a glow per part, and which parts it has a track for), `Rig::blendLocal(a, b, w, mask, onlyTracked)` mixes two of them (per part by the weight times a mask; `onlyTracked`: parts the second has no track for stay as they are, which is what a partial-body layer wants) and `Rig::worldFrom(local, overrides)` builds the poses. `Rig::maskOf(part)` is a part and everything below it.

### State machines (`sim/anim_graph.*`)
```lua
model.graph(m, {
    start = "idle",
    states = {
        idle = { clip = "idle" },
        move = { blend = { param = "speed", points = { {0, "idle"}, {1.4, "walk"}, {4, "run"} } } },   -- a blend space: clips mixed by a parameter, at the same phase (their feet stay in step)
        hit  = { clip = "hit", loop = false, next = "idle", next_fade = 4 },
    },
    transitions = {
        { from = "*",    to = "hit",  when = { hit = "trigger" }, fade = 3 },
        { from = "idle", to = "move", when = { speed = ">0.2" }, fade = 8 },
        { from = "move", to = "idle", when = { speed = "<0.1" }, fade = 10 },
    },
    layers = { { clip = "wave", mask = "arm_r", param = "waving", weight = 1, fade = 6 } },
})
model.param(m, "waving", 1)     model.trigger(m, "hit")     model.state(m)     model.graph(m)   -- take it away
```
- A **state** plays a clip (`loop = false` plays it once, then `next` follows, or the pose stays on the last frame) or blends clips by a **parameter** (`blend`). A **transition** is tried every tick in this order: those of the current state, then those `from = "*"`; the first whose conditions all hold fires, with a cross-fade of `fade` ticks; `when_done = true` waits for a clip that does not loop to finish. A condition is `"trigger"` (a one-shot name, consumed when a transition or layer takes it), a number (`==`), or an operator and a number (`">0.2"`, `"<=3"`, `"!=0"`).
- **Parameters** are numbers by name, at most 64 (`model.param`, MCP `model_param`); `speed` is the engine's: the model's speed in m/s in the plane normal to the up (a placement is not a speed; a clip's own `model.move` is a cut).
- **Layers** play a clip on a part and everything below it, over the state's pose: on while the parameter is above 0.5 (it restarts the clip when it turns on), or once when a trigger of that name fires; the weight fades in and out over `fade` ticks.
- The graph is a function of the tick and the parameters, which are set by logged calls (script calls and the actions `model_graph`, `model_param`, `model_trigger`): a replay poses the same. `model_graph {id, graph, save}` with `save` keeps the graph's text in the model's `.vxm` (the `ANIM` chunk below); a file that has one plays it from the start whenever it is spawned.
- The procedural layer (walk, look-at, IK, springs, ragdoll) lies on top of whatever the graph or the clip says.

### Events on a clip's time line
A clip has `events`: `{ t = 0.25, name = "footstep_l" }` (a time in seconds and a name). When the clip's time passes one (looping clips wrap, a clip that does not loop fires once), the model's event is queued and the game calls the script's `on_anim(model, name, clip)` once per event, in order, after the poses of the tick. Events fire for the state's main clip (the clip with the larger weight of a blend), for layers while they play, and for a plain `play`. Put them in with the Models panel ("events"), `model_clips_edit` (`add_event`), or in the clips JSON (`"events": [{"t": 0.25, "name": "step"}]`). Nothing in the engine acts on a name by itself (no sound is played): the script decides.

### Clip editing as text (`world/rig_json.*` `rigEditClips`)
MCP `model_clips {id}` reads (a summary, the whole clips JSON, the graph and its state), `model_clips_edit {id, ops, save}` changes, all operations or none: `create_clip`, `delete_clip`, `set_clip {name, duration, loop, rename}`, `copy_clip {clip, as}`, `mirror_clip {clip, as}` (parts named `*_l` / `*_r` / `_fl` / `_fr` / `_bl` / `_br` / `left` / `right` swap their tracks; rotations about y and z and the offset along x change sign: a mirror across the x plane, right for a model that faces +z), `set_key {clip, part, t, rot, pos, glow}` (a key within a millisecond is changed, else added; a new key starts with the track's offset and glow at that time), `delete_key`, `add_event`, `delete_event`, `reverse_clip`, `scale_time {clip, factor}` and `import {clips}`. The Models panel has copy, mirror and reverse for the clip and an events list. A clip that is deleted while a graph uses it takes the graph away with a note.

### The file
A rig written with clip events or a graph gets a trailing **`ANIM`** chunk after the clips (and after a `RIGX` chunk when there is one): a version, a length and JSON text `{ "events": { clip: [{t, name}] }, "graph": {...} }` by names. Readers that stop after the clips ignore it; a damaged one is a warning and the rig loads without it. A rig with neither writes the bytes it wrote before.

### 3. The plan, in order

Every item: the data, where it hooks into `AnimatedModels::pose()`, the determinism rules, the tests, the API, the effort. Do them in this order; each is shippable alone.

#### Determinism rules (apply to every item)
- **The poses are simulation state** in this engine, not decoration: the part bodies are kinematic and push dynamic bodies (and the player). So everything here runs once per tick inside `animated.tick`, from the tick's inputs only (origin, rotation, the clip time, the CPU world, the gravity field), with `dmath` sin / cos / atan2, `std::sqrt` (IEEE exact), `std::floor` / `fmod`, and quaternion products. Never `glm::angleAxis`, `glm::rotation`, `glm::slerp` (they call the C library), never frame time, never the GPU. Add to `core/dmath.hpp`: `quatAxisAngle(Vec3 axis, float deg)` (sin / cos from dmath), `quatFromTo(Vec3 a, Vec3 b)` (`q = (1 + a.b, a x b)` normalised with `sqrt`; the antiparallel case picks any perpendicular axis), `frameQuat(Vec3 forward, Vec3 up)` (orthonormalise, build a `Mat3`, `glm::quat_cast` uses `sqrt` only), `nlerp(q0, q1, t)` (a normalised lerp, no trig). Tests of `test_procedural.cpp` already assert bit-equal results of two runs: keep one such case per new item.
- **Nothing reads a pose except the physics.** No Lua getter of a part's pose for gameplay (a `model.pose` for debugging may come later, read-only). The gravity field, the world probe and the ray are the authoritative CPU structures, so a replay and every net peer compute the same pose from the same actions: no pose data goes into the log or on the wire.
- **State lives in `ProceduralState`** (per instance), advanced in `pose()`, reset by `setProcedural`; not saved (a load is a cut, the layer settles within a second, which is what a clip does too). `stateHash` covers the bodies the poses drive; no extra hash.
- **Costs**: a rig has at most 255 parts; a second `Rig::evaluate` per tick (P1) and two rays of ≤ 20 voxel steps per leg (P2) are microseconds. No budget change.

#### P0. Fixes to the layer (half a day) **done (2026-10-21)**

#### P2. Two-bone IK with foot placement (1.5 days) **done (2026-10-21)**
- **Data** (`ProceduralDesc`): `struct Leg { std::string upper, lower, foot; Vec3 pole{0,0,1}; float footHeight = 1.0f /* voxels, ankle pivot above the sole */; float reach = 1.2f /* m, the ray's length below the ankle */; float lift = 0.5f /* m, the ray starts this far above */; }` `std::vector<Leg> legs; bool footPlacement = true; float maxDrop = 0.5f /* m, how far the hips may sink to the lower foot */; float pelvisRate = 0.2f /* per tick */;`. From the rig at `setProcedural`: the rest pivots `hipL = parts[upper].pivot`, `kneeL = parts[lower].pivot`, `ankleL = parts[foot].pivot` (model voxels), bone lengths `L1 = |knee - hip|`, `L2 = |ankle - knee|`, the rest directions. Refuse a leg whose pivots are not a chain (`lower.parent == upper`, `foot.parent == lower`) or whose `L1` or `L2` is < 0.5 voxel. State (`ProceduralState`): per leg `Vec3 targetW` (the ankle's world target, fine voxels), `float groundDelta` (voxels, filtered), `bool planted`; `float pelvisDrop` (voxels, filtered).
- **Where the ankle wants to be**: evaluate pass 1 (the clip plus the walk swing) and read `world1[foot]`'s ankle position in model space: `ankle1 = world1[foot].rot * ankleL + world1[foot].pos`; world: `A = origin + R0 * ankle1` (fine voxels). That is the animated ankle (swinging legs already move it); the IK only corrects it for the ground.
- **The ray** (`world/raycast.hpp` `raycastWorld(world, DVec3 origin, Vec3 dir, float maxDistance)`, the CPU DDA): from `A + upW * lift / kVoxelM` along `-upW` for `(lift + reach) / kVoxelM` voxels; `hit.cell` is the ground voxel, the ground point is `hit.before` centre plus half a voxel toward the normal... simpler and exact on the grid: `groundY = dot(hit.before + 0.5, upW)` along the up axis, i.e. the top face of the hit voxel. If no hit: the foot hangs at the animated place (a ledge). The ray only runs while the leg is in **stance** (the foot moves backward against the body: `cos(2π(cyc + phase)) < 0`) or the model stands still; during swing the target is the animated ankle lifted by the walk cycle, so steps clear stairs. Desired ankle = ground point + `upW * footHeight` (voxels). `groundDelta += (desired - A).up - groundDelta) * 0.35` (filtered, a step onto a stair is 6 ticks); `target = A + upW * groundDelta`.
- **The pelvis**: `pelvisDrop` target = `min(0, min over legs of groundDelta)` clamped to `-maxDrop`, filtered at `pelvisRate`; applied as `rootOffset += upW * pelvisDrop` (so the standing leg is not overstretched on a step down; the other leg bends). Note the root offset moves every part body: that is wanted (the body sinks).
- **The solver** (model space, then into the parents' frames): hip `H` = world1 hip pivot in model space (the clip may have moved it), `T` = `conj(R0) * (target - origin)`; `d = clamp(|T - H|, |L1 - L2| + 0.01, L1 + L2 - 0.01)`; knee angle by the law of cosines: `cosK = (L1² + L2² - d²) / (2 L1 L2)`, `k = dmath::acos(clamp(cosK, -1, 1))` (add `acos` to dmath from `atan2(sqrt(1 - c²), c)`); the bend plane: `dirHT = normalize(T - H)`, `poleP = normalize(pole - dirHT * dot(pole, dirHT))` (`pole` in model space, per leg; a zero projection uses the model's forward, then side); the knee: `K = H + dirHT * L1 * cosA + poleP * L1 * sinA` with `cosA = (L1² + d² - L2²) / (2 L1 d)`; desired world-space frames: `Fu = frameQuat(normalize(K - H), poleP)`, `Fl = frameQuat(normalize(T - K), poleP)`; rest frames `Ru = frameQuat(normalize(kneeL - hipL), poleRest)`, `Rl = frameQuat(normalize(ankleL - kneeL), poleRest)` (computed once at `setProcedural`); the part's model-space rotation must be `Fu * conj(Ru)`; the override is in the **parent's** frame: `over[upper].rot = conj(world1[parent(upper)].rot) * Fu * conj(Ru)`, mode 2, `off = 0` (the hip stays at the clip's offset); for the lower part its parent is the upper, whose new world rotation is `Fu * conj(Ru)`: `over[lower].rot = conj(Fu * conj(Ru)) * Fl * conj(Rl)`. The foot part: keep the clip's local rotation (mode none) or, with a `foot_level = true` option, replace it so the sole is normal to the ground normal (`frameQuat` of the ground normal and forward), mode 2. Then the second `evaluate`.
- **Hook**: in `pose()` after pass 1, before the bodies are written; needs `const World&` and the probe's flags (`AnimatedModels` gets `const World* world` from `main.cpp`; tests pass a `World`).
- **Determinism**: the ray is the CPU DDA on the authoritative world; the filter constants are per tick; `acos` from dmath. A replay sees the same world at the same tick. Net: the same.
- **Tests** (`test_procedural.cpp`): (1) analytic: a 2-bone chain with `L1 = L2 = 8`, target at distance 12 straight down gives a knee angle of `2 acos(12/16)` within 0.1° and the foot at the target within 0.05 voxel, the knee on the pole side; an unreachable target (distance 20) gives a straight leg pointing at it; (2) on a `World` with a floor at y = 32 and a one-voxel step: a standing walker with feet over the step has the stepping foot's ankle `footHeight` above 33 and the other above 32, and the pelvis dropped by at most `maxDrop`; (3) walking across the step (240 ticks) never puts an ankle below its ground, and the pose sequence of two runs is bit-equal; (4) a ledge (no hit) leaves the foot at the animated height; (5) under a side-pointing gravity field the ray goes along `-up` (a wall-walker's feet find the wall).
- **API**: Lua `model.procedural(m, { ik = { legs = { {upper = "leg_l", lower = "shin_l", foot = "foot_l", pole = {0,0,1}}, ... }, foot_placement = true, max_drop = 0.5, foot_height = 1 } })` (legs default from the rig's roles, P4). MCP `model_procedural {id, rules}` with the same JSON (P4 adds the tool).
- **Effort**: solver and frames 0.5 d, ray + filters + pelvis 0.5 d, tests 0.5 d.

#### P3. Foot lock and turning (1 day) **done (2026-10-21)**
- **Foot lock**: when a leg enters stance, pin `targetW` to the ankle's world position at that tick (`planted = true`); while planted the IK targets the pinned point (so the hips move over a fixed foot: no sliding while the body translates or turns); release when the leg leaves stance, or when the stretch `|T - H| > L1 + L2 - 0.5 voxel`, or the pinned foot is more than `maxDrop` under the ground (the ground went away). Standing still: both feet planted.
- **Turn step**: when the model's yaw changes (the agents snap a quarter turn; `R0` changes) and the planted feet's yaw error exceeds 50°, unplant the leg that is **not** carrying (the one whose animated ankle is higher, or alternately), let it swing to its new rest spot over 10 ticks (a lerp of the target with a 2-voxel lift arc), then the other: a two-step turn in place. Determinism: the yaw error is from `R0`, which is an action-driven integer rotation.
- **Smoothed body yaw for snapping agents**: `ProceduralDesc::turnSmoothing = 15` ticks: when `R0` changes by `Δ` (one of the 24 rotations), the root gets a compose override of `conj(Δ)` that decays to identity over `turnSmoothing` ticks (`nlerp`), so the voxel body turns smoothly while the agent's logic stays quarter-snapped. (The bodies move with the pose, so the collision turns smoothly too; the agent's own path logic is untouched.)
- **Tests**: a walker translated 1 m sideways over 30 ticks with both legs in stance keeps each ankle within 0.3 voxel of its pinned point until release; a 90° snap of `R0` produces two foot swings within 30 ticks and ends with both feet under the hips; with `turnSmoothing = 15` the root's world yaw error after the snap decays monotonically to < 1° by tick 15; bit-equal runs.
- **API**: `ik.foot_lock = true` (default with foot placement), `walk.turn_smoothing = 15`.

#### P4. Rig description: roles and joint limits (1.5 days) **done (2026-10-21)**
- **Data** (`world/rig.hpp`): `struct RigJoint { enum Type : u8 { None, Hinge, Ball } type = None; Vec3 axis{1,0,0}; /* model frame */ float lo = 0, hi = 0; /* hinge, degrees */ float cone = 0; /* ball, degrees */ float twist = 0; /* ball, degrees about the axis */ }` on `RigPart` (`joint`), and `struct RigRoles { int hips = -1, head = -1; std::vector<int> spine; struct Limb { int upper = -1, lower = -1, end = -1; Vec3 pole; } ; std::vector<Limb> legs, arms; std::vector<int> tail; Vec3 forward{0,0,1}; }` on `Rig` (`roles`).
- **File**: a trailing chunk after the clips: `"RIGX"`, `u16 version = 1`, per part `u8 type, 3 x f32 axis, 4 x f32 lo hi cone twist`, then the roles as a short JSON text (`u16 len` + bytes, part **names**, not indices). The current reader stops after the clips and ignores trailing bytes (`rig.cpp:494` is the last check, "truncated"; there is no "trailing data" check), so old engines read new files; keep that property (never add a trailing check). Written only when any joint or role is set (a plain rig stays byte-identical). Magic numbers stay `VXM2` / `VXM4`. `test_rig.cpp`: round trip, an old file reads with no roles, a truncated chunk is a warning not a failure.
- **Auto-roles by names** (`Rig::inferRoles()`), applied when the file has none: `hips|pelvis|root`; `head`; `torso|chest|spine*` -> spine; legs from `(leg|thigh|hip)_(l|r|fl|fr|bl|br|0..9)`, `shin|calf|lower_leg` and `foot|paw`; arms from `arm|upper_arm`, `forearm|lower_arm`, `hand`; `tail*`, `antenna*`, `cape` -> tail springs. A leg with only an upper part (the kit's `walker`: `leg_l` / `leg_r`, no shin) has no IK (the walk swing still works) and says so in `model_info`. Joint defaults by role: hips-leg ball 60° cone, knee hinge 0..140° about `side` (bends backward for bipeds, forward for a quadruped's hind leg: by the pole), shoulder ball 170°, elbow hinge -150..0, neck ball 70°, spine ball 20°, tail ball 60°.
- **Limits in the layer**: after pass 2, every part's local rotation is clamped to its joint (a hinge: the angle about `axis` clamped to `[lo, hi]`, the off-axis part removed; a ball: the swing clamped to `cone`, the twist to `twist`) — this is what keeps look-at, springs and IK from bending a knee sideways. (P6 uses the same joints for the ragdoll.)
- **API**: Lua `model.rig(m)` -> a table (parts with parent / pivot / joint, roles, clips); `model.rig(m, { roles = { hips = "pelvis", head = "head", spine = {"torso"}, legs = { {"leg_l","shin_l","foot_l", pole = {0,0,1}}, ... }, arms = {...}, tail = {"tail1","tail2"} }, joints = { knee_l = { type = "hinge", axis = {1,0,0}, lo = 0, hi = 140 }, ... } })` (sets and, with `save = true`, writes the file); the workspace gets ops `rig_role` / `rig_joint`; a manifest may carry `rig = { ... }` for a prefab's model. MCP: `model_rig {id}` (describe), `model_rig_set {id, roles?, joints?, save?}`, `model_procedural {id, rules | null}`, `model_look_at {id, x, y, z | clear}`. `check_project` lints a rig description (unknown part names, a chain that is not parent-linked).
- **Tests**: inference on the walker and on a synthetic quadruped rig; limits: a look rule with `limit_yaw = 170` on a neck with `cone = 70` ends at 70°; a file round trip; `model_rig` JSON equals `model.rig`.

#### P5. Springs v2 (half a day) **done (2026-10-21)**
- `Spring::drive = Accel | Parent | Both` (default Both): the Parent drive is the parent's angular velocity about the spring axis, measured from the parent's world rotation this tick vs. last (`ProceduralState::prevWorldRot` per part, from pass 2 of the previous tick): `ω = 2 * atan2(|v|, w) / dt` of `rot * conj(prev)` projected on the axis; force `-= gainParent * ω` (degrees per rad/s, default 0.15). A chain (`tail1 -> tail2 -> tail3`) then follows naturally: each link is driven by its parent's motion. Add `gravity_sag` (degrees per 1 g along the axis's perpendicular: a cape hangs down, a tail droops under strong gravity) using `upL`.
- **Tests**: a 3-link tail on a model that snaps its yaw by 90° (P3's smoothing off) swings link by link (the peak of link 3 comes ≥ 3 ticks after link 1's) and settles; two runs bit-equal.

#### P6. Ragdoll on a hit (1.5 days for the switch, +1 day for the powered blend) **done (2026-10-21)**
- **P6a, the switch.** `AnimatedModels::ragdoll(id, bool on)` and a rule `ProceduralDesc::ragdollOnHit { float impulse = 40 /* N s on any part */; float recover = 0 /* s, 0 = never */; }`. The trigger: `PhysicsWorld` keeps a per-body "largest contact impulse this step" (`VoxelBody::hitImpulse`, written in `solve()` from the accumulated normal impulse, cleared each step; a cheap float), read in `pose()` for the model's part bodies; a blast's impulse counts (it goes through the same accumulators). Switch: every part body becomes dynamic (`kinematic = false`, restore `mass / invMass / invInertiaBody` that `spawn()` zeroed: keep a copy per part at spawn, `Instance::massOf`), `owned` stays, and joints are added between each part and its parent from the rig's joints (P4; a part without a joint gets a ball joint of 30° at its pivot): `JointDesc{a = child, b = parent, anchor = world pivot, axis = R0 * world.rot * axis, lo / hi / cone from the rig}`. The poses stop driving (`in.ragdoll = true`: `pose()` only reads). The model's `origin` follows the hips body (`origin = hips.pos - R0 * hipsCom`) so `model.pos`, look-at targets and a later recovery stay consistent. `remove()` removes the joints too. Nothing in the hash changes: the bodies and joints are already hashed; the switch is a sim event from deterministic impulses, so a replay switches at the same tick.
- **P6b, the powered blend** (the "blending toward the ragdoll"): instead of dropping the drive, keep the kinematic pose as the **target of joint motors**: each joint gets `springK / springDamping` toward the animated local angle (`setJoint` already changes a hinge's spring at run time; add the same for the ball joint's swing: a spring toward a target quaternion, implemented as a torque on the cone error), with `blend` 1 at the hit decaying to 0 over `fall_time` (default 0.6 s): a hit character staggers for a few ticks, then goes limp. Recovery: `model.ragdoll(m, false)` (or after `recover` seconds when the hips body has slept): ramp `blend` 0 -> 1 toward the rest pose over 0.5 s, and when every part's pose error < 2° / 1 voxel, make the parts kinematic again and remove the joints.
- **Agents**: an agent whose model is ragdolled stops walking (`AgentSystem` sees `models_->find(id)->ragdoll` and holds; an event `agent.on_hit`); `recover` brings it back where it lies (`a.pos` = the hips).
- **Tests**: a walker hit by a 100 N s impulse on the torso (via `phys.applyImpulse`) is dynamic within one tick, has `parts - 1` joints, and falls (hips below the start within 1 s) under gravity; no joint exceeds its limit by more than 5° after 2 s; an impulse below the threshold changes nothing; two runs bit-equal; `ragdoll(id, false)` after 3 s brings the parts back to kinematic with the rest pose within 1 s.
- **API**: Lua `model.ragdoll(m, true | false)`, the rule `ragdoll = { impulse = 40, fall_time = 0.6, recover = 0 }` in `model.procedural`; `agent.spawn{ ragdoll = {...} }`; MCP `model_ragdoll {id, on}`. The `doll` headless script keyword stays for the mannequin.

#### P8. Quadrupeds (1 day) **done (2026-10-21)**
- `walk.gait = "walk" | "trot" | "pace" | "gallop"` or a `gaits = { {name, from_speed}, ... }` ladder; the legs are named `{fl, fr, bl, br}` (or from roles: legs in the order front-left, front-right, back-left, back-right by their pivots' positions along `forward` and `side`). Phase tables (fraction of a cycle): walk `fl 0, br 0.25, fr 0.5, bl 0.75` (lateral sequence); trot `fl 0, br 0, fr 0.5, bl 0.5` (diagonal pairs); pace `fl 0, bl 0, fr 0.5, br 0.5`; gallop (transverse) `bl 0, br 0.1, fl 0.5, fr 0.6` with a suspension (bob up at phase 0.75, `bob * 2`). Switching: a gait change crossfades the phase offsets over half a cycle (`nlerp` of the two limb angles by a 0..1 weight advanced per tick), so no leg jumps. Spine: `roles.spine` parts flex by `spineFlex * sin(2π cyc)` degrees about `side` in a gallop (default 8°), `0` in a walk. Head: the look rule's pitch gets `-bob` coupling (the head bobs with the gallop). IK per leg with a per-leg `pole` (front legs bend backward like an elbow: pole `-forward`; hind legs bend forward at the stifle: pole `+forward`) — the roles' `pole` per limb from P4 covers it.
- **Tests**: a synthetic 4-leg rig at 1 m/s in `walk` has the four legs' peaks a quarter cycle apart in the lateral order; at `trot` diagonal legs are in phase; a gait switch at tick 100 never changes any leg angle by more than 10° between two ticks; bit-equal runs.

### 4. Decisions taken and why
- **Overrides with a replace mode (P1), not a second rig pass by voxels or a separate IK rig**: the leg parts must obey the IK, everything else the clip; one vector per tick with a mode per part is the smallest change to `Rig::evaluate` and keeps the clip editor's data untouched.
- **IK after the walk swing, on its result**: the swing gives the animated ankle (steps lift), the IK only corrects for the ground and keeps feet from sinking into stairs; a pure IK gait (planning each step) is a bigger system with no gain here.
- **The ray on the CPU DDA, in stance only**: it is the authoritative world (determinism), it is cheap, and swinging feet do not need it; the one-pole filters avoid pops when the ray crosses a voxel edge.
- **Rig roles and joints in a trailing chunk, with inference by names**: the kit's models work without an editor round; the chunk keeps old readers valid (no trailing check in the loader) and old files readable; the roles are names so a part rename in the workspace does not corrupt them silently (an unknown name is a warning).
- **Ragdoll by turning the part bodies dynamic (P6a), joints from the rig**: no second set of bodies, no copy of voxels, the hash and the renderer see the same bodies; the powered blend (P6b) is the same joints with springs, so it can come later without redoing anything.
- **Agents keep snapping, the body smooths (P3)**: the agents' path logic and tests stay as they are; the smoothing lives where the other cosmetic-but-deterministic rules live.
- **Gait tables for quadrupeds instead of a physics gait**: the limb API already takes arbitrary phases; a table plus a crossfade gives walk / trot / gallop for every four-legged model in a day.
- **No pose read-back for gameplay**: the TASKS note says poses must stay out of the simulation state unless a rule reads them; here they already drive kinematic bodies (so they are deterministic sim state by construction), and the rule stays: nothing else reads them, so a change to a rule can never desync a replay beyond the body poses, which are hashed.
- **Not done on purpose**: a clip editor, state machines and clip events (TASKS "Next" 2 to 4) are separate; this plan makes the procedural layer complete and the rig description they will need.

## The player's model (a body in the third-person view, a weapon in the first-person view)
The player has no body of its own unless the level gives it one. Both are **rigged `.vxm` models** (the files and clips an agent's model has: `docs/ANIMATION.md` above), **drawn and nothing else**: they live in visual-only animated models (`AnimatedModels(..., visualOnly)`), not in the physics world, so nothing collides with them, they push nothing, they are in no hash and no recording (the file is copied into the clip like any model, so a replay draws them too).
```lua
player.model("models/hero.vxm", { idle = "idle", walk = "walk", run = "run", jump = "jump", swim = "swim", attack = "attack" })  -- the body; clip names default to these
player.model_play("attack" [, speed])      -- a one-shot clip over the walking; when it is over the body goes back to what the player does
player.model(nil)                          -- takes it away (the debug mannequin of the third-person camera comes back)
player.hand_model("models/sword.vxm", { offset = {0.28, -0.28, 0.55}, turn = 0, idle = "idle" })   -- hangs on the camera: metres right, up, forward of it; `turn` degrees about the camera's up
player.hand_play("swing" [, speed])        -- a one-shot (a swing); then the idle clip again;  player.hand_model(nil) takes it away
```
**The body** stands with its feet (the middle of the model's bottom) at the player's feet, faces the player's heading and **stands on the player's up** (a gravity flip turns it over), and picks its clip each tick from what the player does: swimming, in the air (`jump`), running (above 5 m/s), walking (above 0.3 m/s, the clip's speed follows the player's), standing; a clip the model lacks is skipped (it keeps what plays; a model with no walk or run clip is animated by the rules of its roles, as an agent without one: the legs swing by the distance walked). It is drawn from outside: third person, the editor camera and free MCP pictures (`screenshot {eye, target}`); not in the first-person view, where the hand model is. A level with a body does not get the box and nose of the third-person camera. Players 1..7 of a networked session: `player.model(file, opts, who)`.
**The model in the hands** is placed on the camera every frame (not in the simulation), shown in the first-person view only. The model's front (+z) points away from the player at `turn = 0`; a sword is modelled pointing up (+y) and turned about the offset's middle.
Not built: two models per player, a body for the other players' view of an agent-less peer without the file, mouse look of the head (`model.look_at` works on agents only).

**Sizes for the hand model**: the offset is in metres from the camera, the model in voxels of its own size (6.25 cm unless the file has a voxel scale, see "Voxel scale" below: a model at scale 0.6 has voxels of 3.75 cm, so a 34 voxel sword is 1.3 m), and the camera's field of view is 70 degrees: a 34 voxel sword (2.1 m long) at {0.3, -0.3, 0.55} fills the screen like a pillar. A sword of 16 to 22 voxels (1 to 1.4 m) at offset {0.35, -0.05, 1.0} reads as a sword held out in front of the player; a small tool or a wand 8 to 12 voxels at {0.28, -0.25, 0.6}. The body's camera in the third-person view is not drawn when a wall pulls the camera closer than 0.9 m (it would be inside the torso).


## Voxel scale: models drawn with finer voxels than the world's (round 29)

Everything in the world is a 6.25 cm voxel and stays so. A **rigged model** (a `.vxm` with a rig, including a one-part rig for a plain prop) may carry a **voxel scale**: the size of one of its voxels in world voxels, 0.1 to 1
(`Rig::scale`, the JSON key `"scale"` of the file's `ANIM` chunk; old files and old builds read it as 1). The converted character packs are drawn with voxels of 3.75 cm (a human of 49 voxels is 1.8 m): at scale 0.6 they keep
every detail the world's voxel would throw away (faces, beards, straps, spikes).

- **Making one**: `voxelith --convert-vox IN.vox OUT.vxm --vox-unit 0.6 [--materials T.csv --vox-prefix xx]` keeps the voxels and writes a one-part rig with the scale (`--vox-factor` resamples to the world's voxels instead, as before). `model_rig_set` (MCP) and the
  model editor keep the scale when a rig is saved; `Rig::scale` is also what `--rig FILE` shows.
- **Where it is drawn finer**: the player's body (`player.model`), the model in the hands (`player.hand_model`), `model.spawn(file, x, y, z, rot, { visual = true })` (also `scale = 0.5` to override the file's), and an agent
  with `agent.spawn{ model = ..., collision = "proxy" }` (a scale other than 1 implies it, `scale = 0.5` overrides the file's). Such a model is **drawn only**: its parts are bodies for the renderer, not for the physics world (nothing collides with
  them and they are in no hash: the file, which a recording copies, is all the simulation sees). The ray march walks the body's own grid, shadows, texture patterns, the screen rectangle and TAA follow.
- **Agents**: the fine model rides on **one hidden kinematic box** of its size (the union of its parts at rest, rounded up to world voxels, `VoxelBody::hidden`): it blocks, pushes crates and stands in nav as the figure's body does, but individual limbs do
  not push anything and a drawn-only model cannot go limp (`model.ragdoll` answers false). The agent's id stays `0x40000000 + model id`; walking, goals, doors and events are the agent's own. `collision = "parts"` (every part a body: limbs push crates) needs scale 1.
- **Units**: pivots, part offsets, clip positions, joint axes and the procedural layer's `foot_height`, `bob` and `step_arc` stay in the model's own voxels; metres are what the model and the world have in common (the hand offset, `lift`, `reach`, `max_drop`). A model is
  at most 256 voxels per axis, i.e. 256 x scale world voxels (0.6: 9.6 m).
- **Stamping** (`prefab.place`, `edit.model`, the Prefabs panel, `place_model`): a model with a scale is **resampled to the world's voxel** (a world voxel is solid when a quarter of the model voxels under it are, of their commonest material and part): one file serves both uses; a kit figure
  placed as decoration looks as it did before. `check-project` lists the models with a scale.
- **Limits**: the physics world refuses a body with a scale other than 1 (`VoxelBody::scale`; mass, radius and box are in metres for the body's own voxel); at most 48 bodies a 16 x 16 pixel tile (parts count: keep a model under 12 parts); a fine model is 1/s times as many voxels along a ray.
- **The kit's figures** (`assets/prefabs/figures`) are rigged for it (docs/ASSET_CATALOG.md): `player.model("models/human_man_adventurer.vxm", { idle = "idle", walk = "walk", attack = "attack" })`, `model.play(id, "die")` (the clip holds its last pose), `agent.spawn{ model = ..., animation = "clip" }` plays `walk` while it walks.
- Tests: `tests/test_voxel_scale.cpp` (file, body metrics, the same model drawn with doubled voxels at scale 0.5 stands where the plain one does, the legs plant the feet at the same height, agent proxy, stamping) and the GPU test "voxel scale: ..."
  (the same silhouette and shadow for a body of 48^3 voxels at 0.5 and one of 24^3 at 1, still and turned; twice the detail).
