# Foliage: trees by rule, ground cover by table

Two different things (design in `docs/PREFABS_FOLIAGE.md`, part B):
- **Trees, bushes, rocks** are world voxels (models placed with `setModel`): destructible, flammable, in the far levels of detail, saved with the world. A new kind is a model file. *Where* they stand is decided by `scatter{}` (below).
- **Ground cover** (grass tufts, flowers, ferns, reeds ...) is GPU instances rebuilt every frame from the ground's top faces: no CPU state, no collision, no fire. *What* grows on which material is a table (see "Ground cover").

## scatter{}
```lua
n, footprints, stats = scatter{
    models = { {"models/oak.vxm", 4}, {"models/birch.vxm", 3}, "models/bush.vxm" },   -- file or {file, weight}, picked by hash
    box = {x0, z0, x1, z1},             -- voxels (the planner finds the ground in each column)
    spacing = 112, jitter = 0.6, density = 0.5,      -- a cell of `spacing` voxels gets one model with chance `density`, anywhere in the cell by `jitter`
    on = {"grass", "dirt"},             -- surface materials (default: any solid that is not liquid, leaves or wood: no trees on trees)
    height = {20, 300},                 -- band of the surface height (voxels)        slope_max = 0.7   -- rise over run measured 4 voxels each way: 1.0 = 45 degrees, 0.5 = 27
    water_within = {0, 40},             -- distance to the nearest water (voxels): a shore; {80, 100000}: away from water
    avoid = { {x0, z0, x1, z1}, ... },  -- footprints to keep clear (buildings, roads, the footprints an earlier call returned)
    clearings = { scale = 400, threshold = 0.35 },   -- value noise: where it is below the threshold there is a glade
    seed = 7, rotations = true, sink = 1, y_range = {-64, 1500}, max_count = 100000, underwater = false,
}
```
- **A pure function of the parameters and the loaded ground**: the same rule over the same world gives the same placements (a `hash3(cell, seed)` decides everything, no RNG state), so a level scatters on its **first run**, the voxels are saved and a replay re-runs the script. Run it with `if project.first_run()`.
- **Loaded ground only**: a column that is not loaded places nothing and is counted in `stats.unloaded` (the world streams in over the first seconds; the Cove level repeats the call every half second until `unloaded` is 0, a repeat stamps the same voxels). Put the box near the player.
- **Layer a forest**: call it again with the footprints of the first call as `avoid` (trees at 7 m, then bushes at 2.5 m between them, then rocks). Models are stamped through the edit queue (one undo step per call); a tree is a `setModel` of its upright turn (the four turns that keep +y up).
- **Make tree models with solid crowns**: the far levels of detail are a majority vote, a sparse canopy vanishes beyond about 136 m. Worldgen's own trees are not exported: columns whose top is leaves or wood are skipped.
- `stats` = `{cells, unloaded, no_ground, partial, surface, slope, height, water, avoid, clearing, density}` (what was rejected and why; `no_ground` = air all the way down, `unloaded` = the chunk is not loaded yet: retry on that one only; `partial = 1`: the scan budget (4 M column searches, 250,000 cells per call) ran out). A column whose ground lies under more than 2 voxels of liquid is a lake bed and is skipped unless `underwater = true` (a rain film or a puddle is wet ground). Unknown options are errors. The column search skips empty chunks and bricks (`World::topSolidBelow`). Planner: `src/sim/scatter.*` (`planScatter`).
- MCP: `scatter {models:[{file, weight}], box, spacing, ...}` (an action in the log; the footprints stay in the Lua global `scatter_last`).
- Models of the kit (demo level, Lantern Cove): `oak` (56 x 96 x 56 voxels), `birch`, `pine`, `bush`, `rock`, `tree_small`. Make more with `export_region` from a box of the world.

## Ground cover: the type table
`foliage = foliage.csv` in `project.cfg` (the built-in grass without it). Each line is a **type**; the file REPLACES the built-in table (list `grass` again to keep it):
```
# name,surfaces (;),share,density,h_base,h_var,h_step,h_max,blades,half,spread,main,dry,dark,color_mod,dark_count,dry_count,flower_mask,flowers (;),flower_half,stiffness
grass,grass,3,0.61,2,3,3,8,3,0.25,1.5,tuft,tuft-dry,tuft-dark,5,1,1,31,flower-red;flower-yellow;flower-white,0.36,1
clover,grass,1,0.8,1,2,4,3,2,0.3,1.2,clover,clover,tuft-dark,5,0,0,3,clover-flower;clover-pink;clover-flower,0.4,0.7
reeds,sand,1,0.5,4,4,2,8,2,0.18,1.0,reed,reed-dry,reed-dark,5,1,2,0,-,0.3,0.45
```
| column | meaning |
|---|---|
| `surfaces` | materials whose **top face** carries the cover (`grass;dirt`); any material below id 512 |
| `share` | weight among the types on the same surface: a 3 : 1 pair covers three quarters of the cells with the first (up to 4 types per surface: a mixed meadow) |
| `density` | the share of the 2 x 2 voxel cells that carry a tuft |
| `h_base, h_var, h_step, h_max` | blade height in half cubes: `base + hash % var + patch class / step`, at most `max` (8) |
| `blades` | 1..3 per tuft |  `half` | half the cube size in fine voxels (0.25 = half a voxel), `spread` how far the blades stray |
| `main, dry, dark` | colours (materials, never world voxels); `color_mod / dark_count / dry_count`: `hash % color_mod` is dark for the first `dark_count` values, dry for the next `dry_count`, main otherwise |
| `flower_mask, flowers, flower_half` | one blade in `mask + 1` ends in a flower head (0: none) coloured by the three materials |
| `stiffness` | the wind's lean times this: 0 = does not sway (reeds), 1 = grass, up to 4 |
| `patch_scale, patch_density, patch_height, patch_type` | a second, larger octave of noise over the world (`patch_scale` cells of 2 voxels per wavelength, 0 = off): glades (density drops by `patch_density` where it is low), tall patches (`patch_height` adds to the blade height class where it is high), fields of the other type (`patch_type` pushes the pick toward the later types on the same surface where it is high) |
| `taper, lean, splay` | the cube size at the tip relative to the root (1 = a straight stack, 0.5 = a blade), the voxels the tip leans at rest in the blade's own direction, the voxels it leans away from the middle of the tuft (blades radiate) |
| `wet_dark, wet_lean` | what rain does: the blades' shade at wetness 1 (0.75: darker) and the extra lean as a fraction of the wind's (wetness follows `fx.rain`: it rises in 6 s of rain and dries over a minute; render only) |
| `season` | a material the blades turn into as `fx.season(v)` goes from 0 to 1 (not saved: a reload starts at 0) (autumn yellow, winter grey), per blade by hash; render only: nothing in the simulation reads it |
| `sprite` | a `.vxm` (at most 8 x 16 x 8 voxels, at most 128 surface cubes) of the models folder or relative to the table instead of blade stacks: every surface voxel becomes a cube of `half` size standing on the cell, turned by a quarter turn from the cell's hash and leaning with the wind at the top; the model's colours are slots: the type's `dry` / `dark` material, a flower material (the first of `flowers`), anything else `main` (so a mushroom is a stem and a red cap) |
| `under_water` | `1`: the type grows on the **bed under water** (kelp, seaweed, reeds in the shallows) and only there; every other type grows on dry ground only (a lake bed with grass on it is gone). The blades are cut to the water's depth (below about 2.5 m the depth no longer matters). The far tint ignores such types. Costs a second march only for cells under a water surface. |
| `mask` | `r`, `g`, `b` or `a` (`!r` inverts it): a painted mask (below) scales the type's density by that channel; outside the image the density is unchanged |
| `far_ring` | **on by default** (a missing column is on): the type is also drawn in the **coarser rings** beyond the ground ring (see "Range" below), so the meadow reaches to the horizon instead of stopping at 24 m. `0` keeps a type to the ground ring (a plant that should not turn into a distant clump). Blade types only (a sprite, an under-water or a hanging type is not drawn there). |
| `ceiling` | `1`: the type **hangs** from the underside of its `surfaces` instead of standing on their top face: vines under a tree crown or a roof, roots and moss curtains under an overhang, a cave's ceiling. Blades only (not with `sprite`, `under_water` or `far_ring`). A strand is up to 8 cubes of a whole voxel (50 cm), `half = 0.5` is the right cube size. It is drawn within 20 m of the camera, over cells that are open at the camera's own height (a ray straight up from the camera's level finds the ceiling), so it works in caves of any depth and under crowns, but not for a ceiling that is below the camera. A passer-by pushes the strands aside. The type table holds 8 types in all |

**Trampling and scorch** (render only, lost on a restart): a 512 x 512 cell map in absolute toroidal addressing (`foliage_trample.comp`). The disturbers (the player, moving bodies, blasts: up to 32; a blast is a growing, fading wave) press the cover of the cells they touch; the press recovers by one level every four frames (about 17 s), pressed blades lie low and lean in their own direction. A cell whose top is Ember or Char is scorched (the ring of cells around it is singed): shorter, darker blades; the scorch fades over about 4 minutes. Nothing is read back and nothing is saved.

## Range (2026-10-21)
The ground cover is drawn in **rings**: a grid of 384 x 384 cells per ring, each ring one layer of one compute pass, so each ring costs about the same however far it reaches. Ring 0 is the ground ring (cells of 2 voxels, out to `foliage_radius`: 24 m at 380 voxels), ring 1 has cells of 4 voxels (blades twice the size) out to twice the radius (at most 47 m), **ring 3 cells of 8 voxels (blades four times the size) out to four times (at most 94 m), ring 4 cells of 16 voxels (eight times) out to eight times (at most 190 m)**; ring 2 is what hangs (vines under crowns). The blades keep their number of cubes, so a far tuft is a chunky clump whose pixels are about the size of a near blade's; the share of ground a type covers stays the same. Beyond the last ring the far field below tints the ground.
- **Setting `foliage_range`** (metres; `settings.ini`, `--setting foliage_range=100`, the Settings panel's "grass range (m)"): how far the grass reaches; the outermost ring that is drawn is cut there. **Default 200** at high and ultra (low 48, medium 100); 0 draws the ground ring only. The reach is also limited by the radius: at radius 380 the rings end at about 47, 94 and 190 m; a smaller radius (the low presets) gives shorter rings.
- **Cost** (RTX 3070 Laptop, 2560 x 1440, Lantern Cove): the ground ring alone 0.42 to 0.47 ms (`foliageground`) and 1.9 to 2.2 ms (`foliagesplat`); with the rings out to 100 m about +0.1 ms and +0.3 ms, out to 200 m about +0.2 ms and +0.5 to 0.9 ms. Layers that are not needed (the range is inside the radius of the next ring) are not dispatched.
- Far tufts are placed on the ground that the march finds, level 0 or a coarser level of detail; beyond the streamed radius the ground is stepped (8 voxels) and the clumps follow that.

**The far field**: beyond about 15 to 24 m (where the blades thin out) the top faces of cover-bearing materials are tinted toward the cover's colour (the share- and density-weighted `main` colours of the types on the surface) with the same grain and patch classes as the tufts, so a meadow reads as a meadow to the horizon and the 24 m edge is a gradient (`shade.comp`, per-material tints in the material buffer at index 131072 + id; only the top face, so planetoid sides and flipped rooms have none, like the blades). The LOD of the blades is dithered by the cell's hash over a band, not a step. Up to 8 types. New colours are ordinary materials in `materials.csv` (the Lantern Cove file adds reed, moss, fern and clover). `check_project` reads the table and reports unknown materials. Nothing is simulated or stored: the cover is rebuilt each frame from the voxels under the camera (24 m), it does not collide or burn, and it pops in at that distance by design.
Packing for the GPU: `world/ground_cover.*` (`packCover`: 8 types of 48 words, then a per-material entry with up to four type indices and three cumulative cut points of a byte of the cell's hash); the shader side is `shaders/foliage.glsl` / `foliage_ground.comp`. (Lesson: `cmake/Shaders.cmake` now lists `foliage.glsl` and `gi.glsl` as dependencies: a change to an included file used to leave the shaders that include it stale.)


## Paths (2026-10-21)
Stepping on grass presses it down (the player, bodies, blast gusts: the disturbers). The press lives in a **trample map** of 2048 x 2048 cells (256 m, absolute toroidal addressing, 16 MB, GPU only) with two channels per texel:
- the **fast press** (about 17 s) every type shows: the blades lie down where somebody stepped and stand up again;
- the **slow press** (default 600 s) that a type shows only through its **`path`** column (0..1): a blade shows `max(fast, path x slow)`, lying as flat as the type's **`press`** column says (0.7: down to 30 % of its height). Grass `path 0.6`, clover 0.3, moss 1 (stays flat), reeds and sprites 0 (they spring back). Where `path x slow` is above 0.6 the blades take the `dry` colour and lose 20 % of their shade: a trail reads as a lighter, flatter band, fading linearly over the ten minutes.
- The times are the table's: a line `@trample,fast_seconds,slow_seconds` (absent: `17,600`; slow at least fast). It is read and kept by the writer (a hand-written line stays as written), shown by `foliage_list` (`trample`), and not edited by an action yet.
- A stamp is the maximum of what is there and `255 (1 - distance / radius)`: a path is the union of the passes, walking it again refreshes it, flattening never adds up. A blast flattens a crater's grass for the whole ten minutes; a rolling boulder leaves a track.
- **Reach**: the ground ring and the first far ring (cells of 4 voxels, out to about 47 m) read the map, so a trail shows to 47 m; the coarser rings (cells of 8 and 16 voxels) are wider than a trail and do not. 256 m of wrap: a trail 256 m behind the player is the same texels as the ground ahead of them, and by then it is long gone.
- **Cost** (RTX 3070 Laptop, Lantern Cove): `foliagetrample` (recovery of a quarter of the map a frame: a strip of 512 rows, four frames' worth, a dithered fraction of a level) 0.04 ms, `foliagestamp` (600 x 600 cells around the camera) 0.06 ms.
- **Not built: trails that survive a restart.** It would read the slow channel back (a 1 MB block every 2 s), merge it into sparse 64 x 64 tiles on the CPU, and save a file next to the world store: 1.5 days and the first render-to-disk round trip, and a replay could not reproduce it. A path that should stay for good is authored (the typed mask, once painting is built: a stroke of low density and height).

## Painting (2026-10-21)
A **typed mask** (`@mask,foliage_mask.png,ox,oz,8,typed`) says *what grows* instead of scaling one type: per texel R = the type + 1 (0: the surface's own pick), G = the height (128: unchanged, more is taller, less shorter: up to 8 half cubes of `h_step`), B = the density scale (255: the type's own density, 0: nothing grows), A = how much the texel is painted (0: not at all, the other channels are ignored there). A painted type grows on ANY ground (stone, sand, a roof) except where it does not fit (grass under water); the `mask` column of the types is not used with a typed mask. To paint tall grass give the type a high `h_max` and a small `h_step`.
- **The brush** (Foliage window, "Paint": `paint mode`): the editor's tools are off, the left button paints at the look point, Shift + the left button erases, the wheel changes the radius; a circle on the ground shows the radius and the part that paints in full. Modes: *grow this type* (the type selected on the left), *height*, *density*, *erase*. `hardness` is the inner part that paints in full, `opacity` how far one pass moves a texel toward the value. The picture follows the pointer in the same frame: the brush writes the texels into a CPU copy of the mask and the dirty rectangle goes to the GPU through the frame graph (the `coverupload` pass, a band of rows at a time, 1 MB a frame), no reload, no wait.
- **A stroke is an action** (`foliage_mask_stroke`, JSON: mode, type (by name), value, radius, hardness, opacity, up to 256 points in metres: a disc at the first, a capsule to each next). It is a function of the mask before it and of those numbers only, so the live brush, the log and the MCP tool paint exactly the same: the window paints segments live on the mask, and when the button is let go takes the live paint back and logs the stroke, which paints it again. A longer stroke is cut into actions of 256 points. `foliage_mask_fill` fills a box (the window's `fill selection` uses the editor's selection, as a region only: copying or moving a selection does not move the paint under it). Nothing here is simulation state; the hash does not move.
- **Undo** is the window's: this session's last 64 strokes (64 MB of before-images at most, the oldest go first; every stroke is undoable) (the window's `undo stroke` / `redo stroke`, MCP `foliage_mask_undo` / `redo`). Each is a logged `foliage_mask_rect` (the texels as they were, base64), so a replay writes the same bytes; the world's Z is not involved. Deleting or moving a type renumbers what was painted (the texels follow their type; a deleted type's texels fall back to the surface's own pick) and clears the undo stacks.
- **The first stroke** of a project without a typed mask makes one (its first point is logged at once, so the log holds the mask even when the stroke is dropped): 2048 x 2048 texels of 8 voxels (0.5 m, 1 km), centred on the stroke, `foliage_mask.png` next to the table, the `@mask` line added to foliage.csv; the whole table is uploaded once (a wait for the GPU, like a project start). A hand made channel mask is never painted into (the window and the tools say so; add `typed` to its line).
- **Saving**: with the project (or `foliage_save`) the PNG is written when it changed, as an RGBA PNG (the alpha is the painted weight; `writePng(..., withAlpha)`, compressed: the empty 1 km mask is a few KB, the Cove's 512 x 512 about 100 KB). A recording copies the image into `<clip>/foliage_mask_0.png` and the replay reads that copy; the strokes are in the log.
- **MCP**: `foliage_mask_brush {points, radius?, hardness?, opacity?, mode, type?, value?}`, `foliage_mask_fill {box | "selection", mode, type?, value?}`, `foliage_mask_info {at?}`, `foliage_mask_undo`, `foliage_mask_redo`.
- **Not built**: several tiles (a typed mask is one image of at most 2048 x 2048; at texels of 16 voxels that is 2 km), streaming, a `foliage_mask_mode` action to switch an existing mask between channels and typed (edit the `@mask` line).

## Snow (2026-10-21)
A ground cover type with **`snow 1`** is a layer of snow instead of a plant (columns 39 to 43 of the CSV: `snow`, `snow_compress`, `snow_drift`, `snow_drift_scale`, `snow_min`; the Foliage window's "Snow" group; at most one is used, it takes one of the 8 slots). Give it `surfaces *` (it is not looked up: snow lies on every top face), `h_max` = the depth at amount 1 in half cubes (4 = 12.5 cm; up to 8), `main` = the snow's colour (the material `snow`), `dry` / `dry_count` / `color_mod` = old snow sprinkled in, `wet_dark` = the shade when wet. It cannot be a sprite, hang or grow under water (loader, codec and window refuse).
- **How much it snows** is the weather's: Lua `fx.snow(amount[, falling])` (0..1, render only like `fx.season`: nothing in the simulation or the hash reads it; a reload starts at 0, the level script sets it), the Foliage window's preview slider, the `snow` argument of `screenshot` / `foliage_shot`. `falling` = true: the trodden snow fills in four times faster while it snows (the slow channel is shared, so footprints in grass paths fade four times faster too: snow covers them), and `snow_min` applies. Without a snow type in the table `fx.snow` does nothing.
- **Where it lies**: the first thing the sky sees from above the camera (layer 5 of the ground pass, 2 voxel cells, the near radius): any solid top face that is not on fire, so roofs, tree crowns, stone and open ground are covered, the ground under a roof is not, water is not (the bed under a lake gets none). One record per cell, no density dither (nothing flickers).
- **The look**: every cell is four cubes of 1 x 1 voxels, each with its own top: the depth of a quadrant is the mean of the cell's and its three neighbours', so the surface is continuous at 6 cm and a footprint is a smooth dent; beyond 6 m one cube per cell. Depth = amount x `h_max` x drift noise (`snow_drift`, wavelength `snow_drift_scale` cells) x (1 - `snow_compress` x press) x (1 - scorch), at least `snow_min` (melted by fire too) while it is falling (`fx.snow(amount, true)`). The press is the trample map of the Paths section (both channels: a dent stays as long as the slow press, 10 minutes, 2.5 while it snows). The depth is computed once per cell in the ground pass and kept in the record, so a footprint shows one frame late and the splat only reads it. Fire (the scorch) melts the snow in and next to it for 4 minutes. A dent is a little darker.
- **Far away**: beyond about 15 m the top faces of every material (not under water, and only where a short ray straight up (6 m) finds nothing: a floor under a roof, a lintel or a crown stays bare) are tinted toward the snow colour in shade.comp with the same grain and drifts (the snow colour is the 513th entry of the far field tints), so roofs and cliffs far away turn white at no cost.
- **Limits**: the splat skips cubes whose screen box is over 288 pixels (snow; blades 48; the three threads of a cell take every third row of a big box), so within about 0.3 m of the camera the snow has a hole; a trodden trail is a wide dent (the player is a capsule, there are no foot prints); a snow layer exists only in the ground ring (about 24 m at the default radius), not in the far rings.
- **Cost** (RTX 3070 Laptop, 1920 x 1080 headless, Lantern Cove spot 1, snow amount 1 over the whole view): `foliageground` +0.05 ms, `foliagesplat` about 2.0 -> 3.1 ms (+1.2 ms: the per-pixel ray tests of the cubes near the camera, which cover the ground the player sees; with the first design, a cap of 96 pixels and two threads per cell, it was +1.9 ms), `shade` unchanged (the far tint's 6 m ray up is only for top faces beyond 15 m). No snow (amount 0 or no snow type): no cost, the layer is not dispatched. A cheaper design (a height field in the resolve pass: one record fetch per ground pixel, no boxes, est. 0.3 to 0.5 ms) is described in the Round 24 review (docs/HANDOVER.md); worth it if snow becomes a headline feature.

## Bare ground and real snow (2026-10-22)
- A line `@bare,path,gravel` in `foliage.csv` names materials that are **bare ground** (what the wear system turns a path into, docs/WEAR.md): a **painted** type does not grow on them (the surface table's bit 25;
  the table's own types are unaffected: a material with no cover type has none anyway). The line is kept by the writer.
- The weather snow layer is drawn at **half depth** over real snow voxels (`mat::Snow`): powder on packed snow.

## Configurator (2026-10-21)
The **Foliage** window (Windows menu, panel name `foliage`) edits the ground cover table while the game runs; every change reaches the picture in the same frame (no restart, no reload, no wait for the GPU).
- **The list** on the left: the types in table order, red when `packCover` reported the type (an unknown material, more than 4 on one surface, a bad sprite), `(sprite)` / `(water)` / `(hangs)` tags, the surfaces in the tooltip. `new` makes a grass-like type with the name in the field, `copy` duplicates the selected one, `delete`, `up` / `down` (the order matters: `patch_type` pushes toward later types on a surface, and only the first 8 types are used). The header says `n of 8 types`; the selected type's first surface says how many types share it (at most 4).
- **The editor** on the right: every column of the CSV as a slider, checkbox or material combo (a swatch, a filter box), with the range of the CSV reader (one table, `coverColumns()`, serves the reader, the JSON codec and the window) and a tooltip. Colours are materials of the project's `materials.csv`; the 64 tufts strip shows how `color_mod`, `dark_count` and `dry_count` colour them.
- **Live**: a drag changes the table and the picture at once and writes nothing to the log; when the slider is let go one `foliage_set` action carries the whole row. A combo or a checkbox is one action. A recording therefore holds the edits, and the replay shows the same pictures (the table is copied into `<clip>/foliage_0.csv` at the start of a recording and read from there on replay). They are render-only: the state hash does not change.
- **Preview**: `preview this type on the ground ahead` draws the selected type on ANY ground (stone too) in a box of 8 m around the look point, at full density if asked (not for a snow type: the weather's snow slider shows it). `set the weather` has its own wet / season / snow / wind sliders (render only). Nothing is built.
- **Undo / redo** (buttons in the header) are window-local, 64 deep; each step is an ordinary logged `foliage_set` / `foliage_delete`, so a replay sees plain actions and the world's undo (Z) is never involved. Moves up and down are not undone.
- **Saving**: the project's save writes `foliage.csv` when the table changed (the `save` button in the window does it at once). The writer keeps comments, blank lines, the `@mask` line and every line of a type nobody touched exactly as it was; a type that changed is written again with all columns, a new one at the end, a deleted one is gone. A project without a table gets `foliage.csv` and a `foliage = foliage.csv` line in `project.cfg` at the first save.
- **Actions** (all in the log; the text is the JSON of a type with the CSV column names, a partial row changes only its keys): `foliage_set` (a new name needs `surfaces`), `foliage_add`, `foliage_delete` (text = name), `foliage_move` (number = places, text = name). **MCP**: `foliage_list`, `foliage_set`, `foliage_add`, `foliage_delete`, `foliage_save`, `foliage_shot` (a picture of one type in the preview box: `eye`, `target`, `size`, `full_density`, `wet`, `season`, `wind`, `time_of_day`). In a networked session the table is not edited (every machine would need the same file first).

## Under canopies, roofs and piers, caves and ceilings
The ground pass casts a ray down from above. When the first thing it hits has no cover (leaves, wood, a roof), the ray goes on through it (up to three times 48 voxels) and uses the first open voxel below, so grass grows under trees and kelp grows under a pier. Ground that has less than 12 voxels (0.75 m) of air above it under such a roof gets no cover (the blades would stand through a floor laid on the grass); a lake bed has no such limit.
**Caves**: when the ray from above finds nothing that carries cover (a cave under thick rock, bare stone), a second ray goes straight down from the camera's own height, for cells within 20 m, if the cell is open there. So a cave the camera is in gets its floor covered (moss on stone, ferns on dirt), whatever the rock above is. **Ceilings**: a type with `ceiling = 1` (above) hangs from undersides, found by a ray straight up from the camera's height.
Not covered: floors and ceilings of caves the camera is not in and that are below / above the camera's level by more than the rays reach (a ceiling below the camera: a floor of a second storey seen from above), cover on walls, strands longer than 50 cm.

## Painted masks
A line `@mask,paint.png,origin_x,origin_z[,texel_voxels[,typed]]` in the table lays a PNG (at most 2048 x 2048, 8 bit, grey / RGB / RGBA / palette) over the world: texel (0, 0) sits at the fine voxel column
(origin_x, origin_z) and a texel is `texel_voxels` voxels wide (default 8 = 0.5 m, so 512 texels are 256 m). Each type may read one channel (`mask` column): a glade is a dark patch of the channel,
a flower field a bright one. Bilinear, so the edges are soft; the file is relative to the table's folder; read when the table loads (and on its hot reload). The far tint ignores the mask (it
follows the type's average density). Unpainted ground (outside the image) keeps the type's density.
