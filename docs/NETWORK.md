# Networking: deterministic lockstep

Voxelith's simulation is deterministic (a fixed 60 Hz tick, integer voxel coordinates, seeded randomness, the same bits on every machine), so a multiplayer session does not send the world: every peer runs the same simulation from the same inputs, and **only the players' inputs cross the wire**: a few hundred bytes per tick whatever is exploding. This is *lockstep*. (Not rollback: the state is hundreds of MB and a re-simulated tick costs as much as a real one. Not an authoritative server: that throws the determinism away and would have to stream voxel changes.)

```
voxelith --net-host 7777 --net-players 2 [--project ...]        # the host waits for the others, then everybody starts
voxelith --net-join 192.168.1.20:7777 [--project ...]           # a client (the same project, version and settings as the host)
voxelith --net-host 7777 --net-players 4 --net-min 2 --net-open   # starts with two players; up to two more may join later (they replay the session first)
```
`--net-delay T` (host, default 4 ticks = 67 ms): how far ahead inputs are sent; a round trip shorter than that costs nothing, a longer one stalls the world ("NET: ..." in the HUD). `--net-name NAME`, `--net-players N` (2..8). Headless peers (`--headless --script "..." --net-ticks N`) drive their own player with a script and exit after N ticks: that is what the tests do. Open the port (TCP) on the host; the first version has no NAT traversal.

## What is shared
Everyone starts from the same state: the descriptor (engine version and commit, seed, world size, stream radius, the level script's hash with its includes, the material table's hash, the world save, the player count) must be **identical** or the host refuses the client and says which line differs. Then each tick:

1. a peer's own player steps (`Player::step` against its machine's world, which is `delay` ticks behind: the walking feels immediate) and the *state* it reaches, plus the *actions* it took (a dig, a blast, a torch, a push on a body, a button use: each with the numbers it resolved to, exactly as a recording logs them) go out as one **frame** stamped `tick + delay`;
2. the host relays frames to the others (a star);
3. a tick runs when every player's frame for it is here; every peer applies the frames in player order (states first, then actions) and runs the tick: `tickHead()`, `tickTail()`, the same code as a replay;
4. every 60 ticks the peers send their session hash to the host, which compares them and tells everyone; a mismatch stops the session (`DESYNC at tick N`, both logs show where).

The wire format *is* the replay format (`core/replay_event.hpp`): a networked session recorded with `--record` is replayed by `--replay` like any other, and the two peers' logs are identical (the test diffs them). Player lines carry the player's number (`p <tick> ... <id>`; player 0's have none, so a single player's log is what it always was).

## Limits of this version (what the next one should do)
- **The world streams around every player** (`ChunkStreamer::setExtraCentres`: the loaded area is the union of the squares, evicted when no player is near; bodies are frozen only when they are far from all players), so a second player can walk away from the host (the lockstep streamer stops requesting columns at `6 x (2 radius + 1)^2` resident or pending, a count that is the same on every peer. The brick pool of 1 GB holds about **one** area of the default radius 36 of the demo terrain, not six: when it runs out a column fails, which depends on thread timing, so a networked session **stops with an error** that names the limit instead of drifting apart. Keep the players within one area, or start with a smaller `--radius` (about 36 / sqrt(players)).) Vehicles: every player has their own seat (docs/VEHICLES.md). Every player has a hand (docs/HINGES.md, grab): the actions grab / release / throw carry the player, the host's frame loop sets the real sender, nobody takes what another hand holds, a player who leaves lets go. Still centred on the host: rain, the hand, the scripts' notion of "the player" (`player.pos()`), the audio and the picture's far levels of detail (each peer's own picture follows its own camera).
- **Scripts see every player by id** (`player.count()`, `player.pos(i)`, `player.nearest(x, y, z)`, `player.teleport(x, y, z, i)` ..., docs/LUA_API.md); a call without an id means player 0, the host, and `player.teleport` without an id moves every machine's own player. `player.me()` (which player this machine plays) exists in `on_hud` only, because it differs between machines. `body.grab(id, dist, i)` and `vehicle.enter(id, i)` act for the player i. The hand and the seat of the keys are each player's own.
- **Players do not collide with each other** (they are drawn as boxes with a nose); they push bodies and press plates like the one player always did.
- **Joining a running session** works when the host opened it (`--net-open`; `--net-min N` starts the session with N of the `--net-players` slots, the rest wait for late joiners): the joiner takes a free slot, receives the whole history of the session (every frame since tick 1; the host keeps up to 300,000 ticks, 83 minutes), replays it from the same starting world at full speed, tells the host when it is within about 40 ticks of the present, and takes part from the tick the host names (a second and a half ahead of the newest frame; `Join` message to everybody, the `net_absent` / `net_join` actions in every log). The others never wait for it (before its tick it is not a player). **Catch-up time scales with the length of the session** and the speed of the machine (a tick takes what it takes in a replay: a 20 minute session on a machine that replays at 4x real time is 5 minutes; this is not a snapshot of the world) ; a machine that replays slower than 60 ticks a second never catches up with a session that is still running (the joiner keeps replaying and is not told anything). A slot that was used and left is not given out again; a joiner whose replay differs from what the others agreed on (its hashes are compared with theirs while it replays) is refused before it joins, and is only admitted once one of its hashes matched. `paste` is refused in a networked session (the clipboard is a file of one machine), `teleport` moves only the player who pressed it; `undo` / `redo` act on the shared history from any peer. No reconnect for a player that left.
- **Files placed in a session must exist on every peer**: `prefab` (a model file placed from the Prefabs panel, `place_model`) sends the file's name, not its voxels. A model of the engine's starter kit is found in the kit when a peer's project has no copy (`PrefabSystem::kitDir`); any other file (a model you made) has to be in every peer's models folder, or the stamp exists on one machine only. A **workspace model** (docs/MODEL_WORKSPACE.md) cannot be stamped in a networked session at all (`model_to_world`, the panel's click: refused): save it and place the file. The prefab registry (names, places, rotations, slots, variants, parameters) is part of the descriptor, so projects with different registries are refused at the start.
- Grain settling and particle pushes on bodies are off (the sessions are as deterministic as recordings: GPU timing must not change the world).
- TCP only, no encryption, no authentication (play with people you trust; a hostile peer can send any input, including a blast anywhere).

## Determinism across machines
One machine is not enough: two CPUs / libm versions must give the same bits. The build therefore uses `-ffp-contract=off` (no fused multiply-add: clang fuses `a*b+c` on targets that have FMA) and a pinned `-march=x86-64-v2` (`-DVX_SIM_MARCH=...` to change it), and the simulation never calls the C library's `sin cos atan2 asin acos exp log pow cbrt` (glibc picks FMA or non-FMA versions by CPU): `core/dmath.hpp` has deterministic ones (only `+ - * /`, `sqrt`, `ldexp`, `frexp`, which IEEE 754 rounds exactly), also for quaternions (`dmath::angleAxis`, `slerp`) and Lua's `math.sin / cos / tan / asin / acos / atan / exp / log` (the `^` operator and `math.pow`-like uses of non-integer exponents still go through the C library: do not feed them into the simulation; `--check-project` warns about every `^` other than `^2` and about `math.pow`). Where the helpers differ from the C library on purpose: `pow` of a negative base with a non-integer exponent gives 0, `log` of a value <= 0 gives -1e300. The ports (Lua, ...) are built with the same `-ffp-contract=off -march=x86-64-v2` (`triplets/x64-linux-clang.cmake`), and every thread of the engine pins the floating point control word (MXCSR 0x1F80: no flush-to-zero, round to nearest; `core/fpenv.hpp`), which a sound library could otherwise change; the word is part of the lobby's descriptor, together with the session hash after `on_start` (so a level script that differs in what it builds is refused before the first tick). Rendering, audio and tools may use whatever they like.

`tools/xdeterminism.sh` builds the tree a second time with `-march=native` (preset `xdet`; this machine has FMA) and replays recordings made by one binary with the other, both ways, and `tools/net_test.sh BIN1 BIN2` runs the networked session with the two binaries as peers. Hash maps are not iterated in the simulation where order matters (the replay tests across thread counts would have caught it), but two different standard libraries could still differ: build every peer with the same toolchain.

## Details worth knowing
- A held body follows its player's logged pose, so on another machine it is about 4 ticks (67 ms) behind that player. Hot reload and prefab restamping are off in a networked session (they would run on one machine only). Frames are limited (4096 events, 64 numbers an event, 60,000 characters of text): an oversized frame loses its actions, never its player state, and the sender uses the same cut frame it sends. A player who leaves between two hash ticks is not waited for. Lobby ids are the lowest free slot; the names of the others arrive with the start.
- Joining with an older engine: see docs/SAVES.md (a world save of format 2 shows 0 chunks to an engine that predates the header).

## Pieces
`net/wire.*` (framing, frames), `net/socket.*` (TCP, non-blocking), `net/session.*` (the lobby, the relay, the frames, the hash exchange, leaving), `main.cpp` (`netStart`, `netTick`: the same tick sequence the replay uses), `tests/test_net.cpp` (loopback sessions in one process: frames, relay, three players, leaving, desync, refusal), `tools/net_test.sh` (ctest `net`: two processes).

## When a session desyncs
Run both peers with `--record a.log` / `--record b.log`: the files are identical up to the divergence; `VX_HASHCHEAP=1` makes every peer log a per-system hash line at each hash tick (`hashprobe t=...`) so the first differing system names itself; `VX_NETTRACE=1` logs every frame sent and received.
